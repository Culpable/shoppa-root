# Code standards

## Scope and authorities

- Scope: Astro pages, layouts, components, shared data, CSS, tests, validation scripts, and build configuration.
- Formatter and linter authority: no separate formatter or linter is configured. `astro check` is the source validation authority.
- Type authority: `tsconfig.json` and Astro’s generated types.
- Generated-file authorities: `pnpm-lock.yaml` is generated from `package.json`; `dist/` is generated by `pnpm build` and is not hand-edited.

## Formatting and language rules

- Use TypeScript in frontmatter and shared data files. Keep browser JavaScript out unless static HTML and CSS cannot provide the required behaviour.
- Use semantic HTML and plain CSS. Preserve the 33 rules in `test/agent-accessibility.rules.ts` when changing rendered structure.
- Use British English and typographic apostrophes in display copy. Port or update copy only from the sources routed by `AGENTS.md`.

## Naming

- Name Astro components in PascalCase. Name data and utility files in lower camel case or kebab case consistent with nearby files.
- Use descriptive class names based on content roles. Keep global design tokens under the existing `--colour-*`, `--font-*`, `--space-*`, and shape conventions.

## Module and architecture boundaries

- Keep this repository static and marketing-only. Do not add product, widget, API, backend, blog, CMS, or database code.
- Keep route content in `src/pages/`, reusable shell and sections in `src/components/`, common metadata in `src/data/site.ts`, and exact visual values in `src/styles/global.css`.
- Do not add a framework other than Astro or a client-side UI framework.

## Comments and documentation

- Comment non-obvious intent, invariants, business rules, risks, and edge cases. Do not restate syntax.
- Update `DESIGN.md` when a visual rule changes. Update `README.md` when commands, hosting, or deployment behaviour changes.

## Generated files and source-of-truth ownership

- Change dependencies through `package.json`, then run `pnpm install` to regenerate `pnpm-lock.yaml`.
- Run `pnpm build` to regenerate `dist/`. Never edit `dist/` directly.
- Keep `public/CNAME` in place so Astro copies it into `dist/CNAME`.

## Canonical examples

| Concern | Example | Why it is authoritative |
| --- | --- | --- |
| Page shell and metadata | `src/layouts/BaseLayout.astro` | Owns the document shell, self-hosted fonts, identity links, skip link, header, and footer |
| Exact visual values | `src/styles/global.css` | Owns all production tokens, responsive rules, components, and motion |
| Shared navigation | `src/data/site.ts` | Owns route labels and site metadata reused by components |
| Rendered-output rules | `test/agent-accessibility.rules.ts` | Owns the explicit agent and accessibility rules enforced in browser tests |

## Exceptions

- Code blocks may scroll horizontally. No other page region may introduce horizontal scrolling.

## Enforcement and validation

- `pnpm build` - must complete Astro checks and static generation without errors.
- `pnpm test` - must validate build artefacts and pass all desktop and mobile browser checks.
